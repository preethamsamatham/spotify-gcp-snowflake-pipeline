Phase 1

Instrument the load

Capture each MERGE's counts before Snowflake discards them — and cut the credit burn.

1a

Create the log table

One row per (table, run). run_id groups a run's four rows; task_run_id links each to query_history.

CREATE OR REPLACE TABLE spotify_db.raw.load_log (
  log_id        NUMBER AUTOINCREMENT,
  table_name    STRING,
  rows_inserted NUMBER,
  rows_updated  NUMBER,
  loaded_at     TIMESTAMP_NTZ DEFAULT CURRENT_TIMESTAMP(),
  run_id        STRING,
  task_run_id   STRING
);
1b

The capture pattern

The core trick. Run immediately after each MERGE — nothing between, or LAST_QUERY_ID() points at the wrong statement. A NOT-MATCHED-only MERGE (the bridge) has no "rows updated" column, so hardcode 0 there.

INSERT INTO load_log (table_name,run_id,task_run_id,rows_inserted,rows_updated)
SELECT 'songs', :run_id, LAST_QUERY_ID(),
       "number of rows inserted","number of rows updated"
FROM TABLE(RESULT_SCAN(LAST_QUERY_ID()));
1c

The full rebuilt load task

Daily schedule, all four MERGE+capture pairs, and the pipeline_state handoff as the last statement. Run in its own worksheet.

CREATE OR REPLACE TASK load_spotify_task
  WAREHOUSE = spotify_wh
  SCHEDULE = 'USING CRON 0 3 * * * America/Chicago'
AS
BEGIN
  LET run_id STRING := UUID_STRING();
  TRUNCATE TABLE songs_staging;
  TRUNCATE TABLE albums_staging;
  TRUNCATE TABLE artists_staging;
  TRUNCATE TABLE song_artists_staging;
  COPY INTO songs_staging FROM @spotify_stage PATTERN='.*/songs_.*\\.csv' FILE_FORMAT=spotify_csv_format;
  COPY INTO albums_staging FROM @spotify_stage PATTERN='.*/albums_.*\\.csv' FILE_FORMAT=spotify_csv_format;
  COPY INTO artists_staging FROM @spotify_stage PATTERN='.*/artists_.*\\.csv' FILE_FORMAT=spotify_csv_format;
  COPY INTO song_artists_staging FROM @spotify_stage PATTERN='.*/song_artists_.*\\.csv' FILE_FORMAT=spotify_csv_format;

  MERGE INTO songs t USING (SELECT * FROM songs_staging QUALIFY ROW_NUMBER() OVER (PARTITION BY song_id ORDER BY added_at DESC)=1) s ON t.song_id=s.song_id WHEN MATCHED THEN UPDATE SET t.name=s.name,t.duration_ms=s.duration_ms,t.explicit=s.explicit,t.track_number=s.track_number,t.album_id=s.album_id,t.added_at=s.added_at WHEN NOT MATCHED THEN INSERT (song_id,name,duration_ms,explicit,track_number,album_id,added_at) VALUES (s.song_id,s.name,s.duration_ms,s.explicit,s.track_number,s.album_id,s.added_at);
  INSERT INTO load_log (table_name,run_id,task_run_id,rows_inserted,rows_updated) SELECT 'songs',:run_id,LAST_QUERY_ID(),"number of rows inserted","number of rows updated" FROM TABLE(RESULT_SCAN(LAST_QUERY_ID()));

  MERGE INTO albums t USING (SELECT * FROM albums_staging QUALIFY ROW_NUMBER() OVER (PARTITION BY album_id ORDER BY album_id)=1) s ON t.album_id=s.album_id WHEN MATCHED THEN UPDATE SET t.name=s.name,t.release_date=s.release_date,t.total_tracks=s.total_tracks WHEN NOT MATCHED THEN INSERT (album_id,name,release_date,total_tracks) VALUES (s.album_id,s.name,s.release_date,s.total_tracks);
  INSERT INTO load_log (table_name,run_id,task_run_id,rows_inserted,rows_updated) SELECT 'albums',:run_id,LAST_QUERY_ID(),"number of rows inserted","number of rows updated" FROM TABLE(RESULT_SCAN(LAST_QUERY_ID()));

  MERGE INTO artists t USING (SELECT * FROM artists_staging QUALIFY ROW_NUMBER() OVER (PARTITION BY artist_id ORDER BY artist_id)=1) s ON t.artist_id=s.artist_id WHEN MATCHED THEN UPDATE SET t.name=s.name WHEN NOT MATCHED THEN INSERT (artist_id,name) VALUES (s.artist_id,s.name);
  INSERT INTO load_log (table_name,run_id,task_run_id,rows_inserted,rows_updated) SELECT 'artists',:run_id,LAST_QUERY_ID(),"number of rows inserted","number of rows updated" FROM TABLE(RESULT_SCAN(LAST_QUERY_ID()));

  MERGE INTO song_artists t USING (SELECT DISTINCT song_id,artist_id FROM song_artists_staging) s ON t.song_id=s.song_id AND t.artist_id=s.artist_id WHEN NOT MATCHED THEN INSERT (song_id,artist_id) VALUES (s.song_id,s.artist_id);
  INSERT INTO load_log (table_name,run_id,task_run_id,rows_inserted,rows_updated) SELECT 'song_artists',:run_id,LAST_QUERY_ID(),"number of rows inserted",0 FROM TABLE(RESULT_SCAN(LAST_QUERY_ID()));

  INSERT INTO spotify_db.raw.pipeline_state (run_id,completed_at,tables_loaded)
    SELECT :run_id, CURRENT_TIMESTAMP(), COUNT(*) FROM spotify_db.raw.load_log WHERE run_id=:run_id;
END;
1d

The credit fix — 280x

Was '5 MINUTE': 288 runs/day, ~8.4 credits/day, 87% waste. Matched to once-daily data arrival.

ALTER TASK load_spotify_task SET SCHEDULE = 'USING CRON 0 3 * * * America/Chicago';

Phase 2

Monitor

Hand the run identity from load to digest explicitly, and classify every run.

2a

The handoff table

A row's existence = "the run finished." A mid-flight abort writes no row, so the digest correctly reports it as failed.

CREATE OR REPLACE TABLE spotify_db.raw.pipeline_state (
  run_id        STRING,
  completed_at  TIMESTAMP_NTZ,
  tables_loaded NUMBER
);
2b

The digest-staging table

What the digest would email — proven before SendGrid exists.

CREATE OR REPLACE TABLE spotify_db.raw.digest_log (
  digest_id      NUMBER AUTOINCREMENT,
  fired_at       TIMESTAMP_NTZ DEFAULT CURRENT_TIMESTAMP(),
  load_state     STRING,
  load_run_id    STRING,
  tables_logged  INT,
  new_rows       INT,
  refreshed_rows INT,
  subject_line   STRING
);
2c

The digest task

Independent schedule, not AFTER — a chained child fires only on parent success, so it would go silent on the morning the load breaks. Reads the handoff, classifies, composes a subject.

CREATE OR REPLACE TASK digest_task
  WAREHOUSE = spotify_wh
  SCHEDULE = 'USING CRON 20 3 * * * America/Chicago'
AS
BEGIN
  LET latest_run STRING := (SELECT run_id FROM spotify_db.raw.pipeline_state
                            WHERE completed_at >= DATEADD('hour',-2,CURRENT_TIMESTAMP())
                            ORDER BY completed_at DESC LIMIT 1);
  INSERT INTO spotify_db.raw.digest_log
    (load_state, load_run_id, tables_logged, new_rows, refreshed_rows, subject_line)
  SELECT
    CASE WHEN agg.tables_logged IS NULL THEN 'NO_RUN'
         WHEN agg.tables_logged < 4     THEN 'PARTIAL'
         ELSE 'COMPLETE' END,
    :latest_run, agg.tables_logged, agg.new_rows, agg.refreshed_rows,
    CASE WHEN agg.tables_logged IS NULL THEN 'ALERT Spotify pipeline: no load run detected'
         WHEN agg.tables_logged < 4     THEN 'ALERT Spotify pipeline: partial load (' || agg.tables_logged || '/4 tables)'
         WHEN agg.new_rows > 0          THEN 'Spotify pipeline: ' || agg.new_rows || ' new rows'
         ELSE 'Spotify pipeline: no changes' END
  FROM (
    SELECT COUNT(*) AS tables_logged, SUM(rows_inserted) AS new_rows, SUM(rows_updated) AS refreshed_rows
    FROM spotify_db.raw.load_log WHERE run_id = :latest_run
  ) agg;
END;
Phase 3

The email function

A headless program: key-pair auth, read the run + GCS files, compose the HTML.

3a

Generate the RSA key pair

A Cloud Function has no browser, so browser-SSO can't work at 3:20 AM. Key-pair auth: sign with the private key, Snowflake verifies with the public. -topk8 = PKCS#8 (the only format Snowflake accepts); -nocrypt because Secret Manager handles encryption.

openssl genrsa 2048 | openssl pkcs8 -topk8 -inform PEM -out snowflake_key.p8 -nocrypt
openssl rsa -in snowflake_key.p8 -pubout -out snowflake_key.pub
echo "*.p8" >> .gitignore
3b

Register the public key

Produce the one-line body with the machine — never by hand (a hand-join once dropped the trailing exponent block and Snowflake rejected it).

grep -v "PUBLIC KEY" snowflake_key.pub | tr -d &#x27;\n'
ALTER USER PINTU SET RSA_PUBLIC_KEY='<paste the one-line output>';
DESC USER PINTU;   -- confirm RSA_PUBLIC_KEY_FP set AND HAS_KEYPAIR=true

3d

digest_function/main.py

Dual-mode: local reads the .p8 and writes a preview; RUNTIME=cloud reads Secret Manager and sends. This let the read/compose logic be proven on the laptop before any deploy.

import os, re
from cryptography.hazmat.primitives import serialization
from google.cloud import storage
import snowflake.connector

ACCOUNT = "GIHJUIA-ZR03463"
USER = "PINTU"
BUCKET = "spotify-etl-preetham"
PROCESSED_PREFIX = "raw_data/processed/"
TRANSFORMED_PREFIX = "transformed_data/"
GCP_PROJECT = "python-gcp-snowflake"
EMAIL_TO = "mukundmk1990@gmail.com"
EMAIL_FROM = "mukundmk1990@gmail.com"
DATE_RE = re.compile(r"_(\d{8})_")
IS_CLOUD = os.environ.get("RUNTIME") == "cloud"

def _secret(name):
    from google.cloud import secretmanager
    client = secretmanager.SecretManagerServiceClient()
    path = f"projects/{GCP_PROJECT}/secrets/{name}/versions/latest"
    return client.access_secret_version(name=path).payload.data

def get_private_key():
    pem = _secret("snowflake_key") if IS_CLOUD else open("snowflake_key.p8","rb").read()
    pkey = serialization.load_pem_private_key(pem, password=None)
    return pkey.private_bytes(
        encoding=serialization.Encoding.DER,
        format=serialization.PrivateFormat.PKCS8,
        encryption_algorithm=serialization.NoEncryption())

def get_latest_run():
    conn = snowflake.connector.connect(
        account=ACCOUNT, user=USER, private_key=get_private_key(),
        warehouse="SPOTIFY_WH", database="SPOTIFY_DB", schema="RAW")
    cur = conn.cursor()
    cur.execute("SELECT run_id, completed_at, tables_loaded FROM pipeline_state ORDER BY completed_at DESC LIMIT 1")
    row = cur.fetchone()
    if row is None:
        cur.close(); conn.close(); return None, []
    run_id, completed_at, tables_loaded = row
    cur.execute("SELECT table_name, rows_inserted, rows_updated FROM load_log WHERE run_id = %s ORDER BY table_name", (run_id,))
    tables = cur.fetchall()
    cur.close(); conn.close()
    return (run_id, completed_at, tables_loaded), tables

def _latest_date(blobs):
    ds = [DATE_RE.search(b.name).group(1) for b in blobs if DATE_RE.search(b.name)]
    return max(ds) if ds else None

def list_processed():
    client = storage.Client(project=GCP_PROJECT)
    out = []
    for b in client.list_blobs(BUCKET, prefix=PROCESSED_PREFIX):
        if b.name.endswith("/"): continue
        out.append((b.name.split("/")[-1], b.size, b.download_as_text().count("\n")+1))
    return out

def list_transformed_latest():
    client = storage.Client(project=GCP_PROJECT)
    blobs = [b for b in client.list_blobs(BUCKET, prefix=TRANSFORMED_PREFIX) if not b.name.endswith("/")]
    latest = _latest_date(blobs); out = []
    for b in blobs:
        m = DATE_RE.search(b.name)
        if m and m.group(1) == latest:
            out.append((b.name.split("/")[-1], b.size, max(b.download_as_text().count("\n")-1,0)))
    return sorted(out), latest

def build(run, tables, processed, transformed, latest_date):
    run_id, completed_at, tables_loaded = run
    new_rows = sum(t[1] for t in tables)
    complete = tables_loaded == 4
    if not complete:
        subject, state, color = f"Spotify pipeline: partial load ({tables_loaded}/4 tables)", f"PARTIAL ({tables_loaded}/4)", "#e0a800"
    elif new_rows > 0:
        subject, state, color = f"Spotify pipeline: {new_rows} new rows", "COMPLETE", "#1DB954"
    else:
        subject, state, color = "Spotify pipeline: no changes", "COMPLETE", "#1DB954"
    # ... compose HTML tables for tables / processed / transformed ...
    return subject, "<html>...</html>"

def send_email(subject, html):
    from sendgrid import SendGridAPIClient
    from sendgrid.helpers.mail import Mail
    msg = Mail(from_email=EMAIL_FROM, to_emails=EMAIL_TO, subject=subject, html_content=html)
    SendGridAPIClient(_secret("sendgrid_api_key").decode()).send(msg)

def run_digest():
    run, tables = get_latest_run()
    if run is None:
        return "Spotify pipeline: no load run detected", "<p>pipeline_state empty.</p>"
    processed = list_processed()
    transformed, latest = list_transformed_latest()
    return build(run, tables, processed, transformed, latest)

def digest_pipeline(request):          # Cloud Function entry point
    subject, html = run_digest()
    send_email(subject, html)
    return (subject, 200)

if __name__ == "__main__":             # local entry point (no send)
    subject, html = run_digest()
    open("digest_preview.html","w",encoding="utf-8").write(html)
    print("SUBJECT:", subject)

Gotchas learned the hard way

Ten things that cost real time — each one now a one-line rule.

Capture sits immediately after its MERGE

LAST_QUERY_ID() is positional. A statement in between makes RESULT_SCAN read the wrong result — a loud 'invalid identifier' error, or (worse) silently wrong numbers. Safe inside the fixed task body; fragile when run by hand.

NOT-MATCHED-only MERGE has no 'rows updated' column

The bridge MERGE only inserts, so its result set omits that column. Hardcode 0.

CREATE OR REPLACE TASK always lands suspended

RESUME after every rebuild, then verify with GET_DDL and SHOW TASKS.

Ctrl+A grabs the whole worksheet

It once smuggled a stray GET_DDL into a task body. Keep task definitions and scratch queries in separate worksheets.

LET x := (SELECT ...) can silently return null

In Snowflake Scripting the subquery-assignment returned null with no error. Inline the expression instead.

Never hand-transcribe an RSA key

A hand-join dropped the trailing exponent block. Pipe it: grep -v "PUBLIC KEY" key.pub | tr -d '\n'.

'JWT token is invalid' = wrong account identifier

The connection reached Snowflake; only the signature/issuer was rejected. Use the identifier that authenticates, not the locator or a stale one.

printf is not a PowerShell command

It failed and the key had been exposed. Use a temp file for secret upload; regenerate any exposed key.

gen2 Cloud Functions are Cloud Run

The caller needs roles/run.invoker for OIDC — even your own scheduler.

Verify state, don't trust silence

GET_DDL / SHOW TASKS / re-query after every change. 'Successfully created' with no error is not proof the object changed.
